# الصفحات المعلوماتية

الوحدة متاحة من القائمة الجديدة «الصفحات المعلوماتية». العرض للمستخدمين بعد الدخول، والإدارة والإصدارات والسجلات لمدير النظام (UserType / UsersMembers.Type = 1).

## الاستخدام

- صفحة المحتوى تعرض ترويسة تضم العنوان ورقم الإصدار وتاريخ إنشاء الإصدار المعروض بتوقيت عمّان وزر تبديل اللغة، يليها المحتوى مباشرة. الملخص محفوظ للتحرير والإصدارات لكنه لا يظهر في صفحة الاطلاع. معاينة إصدار قديم تعرض تاريخه هو، وليس تاريخ آخر تعديل للصفحة.

- عنصر «الصفحات المعلوماتية» في القائمة رابط مباشر دون عناصر فرعية. يعرض Index للموظف بطاقات الصفحات المنشورة والمسموح بها، ويفتح Manage لمدير النظام. لكل صفحة عنوان وملخص وتفاصيل مستقلة بالعربية والإنجليزية، مع تبديل لغة العنوان والنص مباشرة بزر type=button عبر detail-language.js دون إعادة تحميل أو PostBack. تُحمَّل اللغتان بعد التحقق من الصلاحية وتُنقّحان على الخادم؛ lang يحدد اللغة الأولية فقط، ويحفظ حقل مخفي لغة العرض عند تحديثات مؤقت الموظفين دون إنشاء زيارة إضافية.
- زر «رابط الصفحة» يفتح نافذة تحتوي رابط الموظف ورابط العميل، مع زر نسخ مستقل لكل رابط عرض مطلق دون معاينة أو رقم إصدار. فتح الرابط يتطلب الدخول وإتاحة الصفحة وفق إعدادات النشر. عند تعذر النسخ التلقائي يظهر الرابط لنسخه يدويًا.
- «إدارة الصفحات»: إضافة وتعديل ومعاينة وإصدارات وسجلات وحذف منطقي، وبحث بالعنوان. قائمة منفصلة لأرشيف المحذوفات تحفظ وصول المدير إلى التاريخ.
- «مسودة» تخفي الصفحة مهما كانت إعدادات نشرها. «منشورة» مع نشر فوري تظهر فور الحفظ وتبقى حتى إلغاء النشر أو الحذف. اختيار «نشر مجدول» يلزم تاريخ ووقت بداية ونهاية حتى عند تجهيزها كمسودة.
- جميع حقول الجدولة والعرض بتوقيت عمّان، والتخزين UTC. تبدأ الإتاحة عند البداية وتنتهي عند وقت النهاية بالضبط. شرط الإتاحة يطبق داخل SQL على القائمة والتفاصيل؛ لا يحتاج مؤقتًا أو مهمة مجدولة. يستطيع المدير معاينة غير المتاح.
- العنوان والملخص والتفاصيل باللغتين إلزامية؛ حدودها 250 و2000 و100000 حرف على الترتيب. ترتيب العرض عدد صحيح غير سالب.
- يستخدم المحرران CKEditor الموجود في المشروع. يدعم النص المنسق والعناوين والقوائم والجداول والروابط والمحاذاة. يُعاد بناء المحتوى بقائمة HTML مسموحة على الخادم؛ السكربتات والإطارات وأحداث HTML والمحتوى التنفيذي غير مسموح بها. الصور والمرفقات ليست جزءًا من هذه الوحدة.

## الإصدارات والسجلات

- الإصدار 1 عند الإنشاء. تعديل محتوى اللغتين أو الحالة أو الجدولة أو الترتيب ينشئ إصدارًا جديدًا. حفظ قيم لم تتغير أو تعديل الصلاحيات وحدها لا ينشئ إصدار محتوى. الحذف المنطقي ينشئ إصدار حذف إضافيًا. لا تُعدّل النسخ السابقة.
- يمكن معاينة أي إصدار سابق من شاشة الإصدارات، بما في ذلك إصدارات الصفحة المحذوفة. زر «استرجاع هذا الإصدار» للمدير يعيد المحتوى باللغتين وإعدادات النشر والترتيب كإصدار جديد، ويسجل المصدر والمنفذ والوقت. تبقى صلاحيات الاطلاع الحالية مستقلة تمامًا. لا يسمح باسترجاع الإصدار الحالي أو إصدار حذف، ولا بإحياء صفحة محذوفة من هذا الزر. تبقى الجدولة المنتهية مخفية بعد الاسترجاع.
- كل إنشاء وتعديل وحذف يسجل رقم المستخدم ونسخة من اسمه من قاعدة البيانات والتاريخ والوقت. تغيير اسم الموظف لاحقًا لا يغير الاسم التاريخي المسجل.
- كل فتح عادي لصفحة التفاصيل يسجل زيارة بالإصدار واللغة واسم الموظف والوقت. المعاينة الإدارية تسجل كمعاينة منفصلة. إعادة تحميل الصفحة زيارة جديدة؛ تبديل اللغة المحلي وتحديث عدادات القائمة لا يولدان زيارة جديدة.
- شاشة السجلات تعرض 50 سجلًا في الصفحة، وتدعم التصفية بالموظف ونوع العملية. رقم الإصدار يفتح الإصدارات، والسجلات متاحة من شريط إدارة الصفحات فقط.
- الحفظ والحذف ينفذان داخل معاملة تضم النسخة والسجل. رقم الإصدار المتوقع مع قفل تحديث يمنع الكتابة فوق تعديل مدير آخر. كل إجراءات القراءة والكتابة تتحقق من الحساب الفعال ودوره، إضافة إلى تحقق صفحات ASPX.

## صلاحيات الاطلاع

- كل صفحة مرتبطة بعلامة تجارية واحدة أو عدة علامات عبر `Information_Page_Brands`. اختيار علامة فعالة واحدة على الأقل إلزامي عند الإنشاء والحفظ من الشاشة. تعرض قائمة الإدارة أسماء العلامات، ويستخدم نموذج التعديل قائمة Select2 متعددة الاختيار من القالب الحالي.
- الترقية تربط الصفحات السابقة بعلامة «بروستو» مرة واحدة، دون تعديل محتواها أو إصداراتها أو أنواع المستخدمين المخولة. تتحقق من وجود علامة فعالة واحدة بهذا الاسم بدل افتراض رقم ثابت. تسجل عملية الترحيل باسم نظام واضح وActorID=0، وتزيد AccessRevision لمنع حفظ نماذج قديمة فوق الربط الجديد. إعادة التطبيق لا تعيد ضبط اختيارات العلامات.
- إتاحة الصفحة = علامة المستخدم الحالية الفعالة ضمن العلامات المحددة **و** صلاحية نوع المستخدم **و** شروط النشر والجدولة. يطبق الشرط في قائمة الموقع والرابط المباشر و`GET /api/Get_InfoPages`؛ لا يعتمد على BrandID مرسل من المتصفح أو الهاتف. المستخدم بلا علامة لا يرى هذه الصفحات. تغيير علامة الحساب أو إيقاف العلامة يسري في الطلب التالي.
- إدارة جميع الصفحات ومعاينة إصداراتها تبقى لمدير النظام، أما الاطلاع العادي بما فيه حساب المدير وواجهة الهاتف فيخضع للعلامة. «جميع أنواع المستخدمين» تعني جميع الأنواع ضمن العلامات المحددة، ولا تعني جميع العلامات.
- الجمهور والعملاء والعلامات وأنواع المستخدمين إعداد وصول مشترك تحميه AccessRevision. يحفظ المحتوى والصلاحيات في معاملة واحدة؛ رفض العلامات أو تعارض نسخة الوصول يتراجع عن كامل الحفظ. استرجاع المحتوى لا يعيد علامات قديمة، وتغيير العلامات وحدها يسجل الأسماء قبل/بعد دون إصدار محتوى جديد.

- داخل نموذج الصفحة اختر الجمهور: الموظفون (كل الأنواع أو أنواع محددة)، العملاء (كل العملاء أو عملاء محددون بالاسم)، أو الجميع (كل الموظفين وكل العملاء). تُصفّى قائمة العملاء محليًا وفق العلامات المختارة، مع بحث بأسماء العملاء دون PostBack. تغيير العلامات يحتفظ بالاختيارات التابعة لها ويزيل العملاء الخارجين عنها مع توضيح ذلك، وتُعطّل القائمة عند عدم وجود علامة أو عملاء. يتحقق SQL من الارتباط أيضًا عند الحفظ. تظل العلامات التجارية والنشر والجدولة شروطًا إلزامية. الصفحات السابقة تظل للموظفين فقط افتراضيًا. تظهر روابط العملاء في بوابتهم، وتتحقق صفحة التفاصيل من صلاحية العميل الحالية عند كل طلب. زر رابط الصفحة يفتح نافذة بروابـط الموظف والعميل وزر نسخ مستقل لكل رابط؛ صلاحيات الجمهور تظل مطبقة عند فتح الرابط.
- تطبق الصلاحيات على القائمة والرابط المباشر والروابط المضمنة بصفحة أخرى، مع استمرار اشتراط النشر والفترة الزمنية. لمدير النظام حق الإدارة والمعاينة دائمًا.
- AllUserTypes وAccessRevision وجدول Information_Page_Roles يمثلون الصلاحيات الحالية؛ لا تُضاف الصلاحيات إلى Information_Page_Versions. تغييرها يسجل إجراء access مع الأنواع قبل التغيير وبعده واسم المدير والوقت. استرجاع المحتوى لا يغير الصلاحيات أو رقم مراجعتها.
- حفظ المحتوى والصلاحيات في النموذج معاملة واحدة؛ إذا رُفض اختيار الأنواع لا يُنشر المحتوى جزئيًا. حماية مستقلة برقم AccessRevision تمنع الكتابة فوق تعديل صلاحيات أحدث.
- السجلات تتضمن مرشحي «تعديل صلاحيات الاطلاع» و«استرجاع إصدار سابق» مع عمود تفاصيل العملية.

## الملفات والتثبيت

- الصفحات في `Portal/Modules/Information_Pages`: Index وManage وEdit وView وHistory وLogs.
- `InformationPagesData.vb`: الاتصال بالإجراءات المسماة، والتحقق من المحتوى والتواريخ.
- `InformationPagesPage.vb`: التحقق من الجلسة والصلاحية، ربط ViewState بالجلسة، ومنع تخزين الصفحات في cache.
- `001_Schema.sql`: الجداول Information_Pages وInformation_Page_Versions وInformation_Page_Logs.
- `002_Procedures.sql`: سبعة إجراءات للعرض والحفظ والحذف والإصدارات والسجلات. تستخدم ADO.NET ومعاملات SQL محددة الأنواع، دون تعديل DBML الحالي.
- `003_Access_Restore_Schema.sql` يضيف صلاحيات الأنواع الحالية ومرجع إصدار الاسترجاع وتفاصيل السجلات دون تغيير المحتوى الموجود. `004_Access_Restore_Procedures.sql` يضيف قراءة أنواع المستخدمين وحفظ الصلاحيات واسترجاع إصدار. Apply.ps1 يطبق الملفات بالترتيب المذكور أدناه، ويدعم ConfigPath اختياريًا لقاعدة اختبار منفصلة.
- `Apply.ps1` يقرأ اتصال Portal ويطبق البنية والإجراءات داخل معاملة. قابل لإعادة التشغيل دون حذف البيانات.
- ربط العلامات: ترتيب التطبيق الحالي 001 ثم 003 ثم 005_Brand_Access_Schema ثم 006_Brand_Access_Procedures ثم 004 ثم 002 عبر `Apply.ps1`. إذا كان MobileApi_InfoPages مثبتًا، يُحدَّث هذا الإجراء وحده من ملفه المعتمد في Mobile_API ضمن المعاملة نفسها؛ لا يعاد تطبيق إجراءات تسجيل الدخول القديمة. التثبيت الجديد للهاتف يحتاج مخطط الصفحات ودالة Information_Pages_ForBrand أولًا.
- `Save_Information_Page` يضيف `@Brands xml` بالشكل `<brands><brand id="29"/><brand id="30"/></brands>` مع `@AllTypes` و`@ExpectedAccessRevision`؛ الإنشاء دون علامات مرفوض. استدعاءات تعديل المحتوى القديمة التي لا ترسل @Brands تحتفظ بالربط الحالي. لا تغير في DBML أو بنية استجابة الهاتف.
- `TestBrandAccess.ps1` ينشئ قاعدة محلية معزولة بحسابات وعلامات مصطنعة، ويختبر الترحيل والتعدد وعزل العلامات والقائمة والرابط وSQL الهاتف والصلاحيات والتزامن المنطقي والاسترجاع والتراجع عند الفشل، ويشغل اختبارات الصفحات والاسترجاع السابقة. يحذف قاعدته افتراضيًا؛ `-KeepForUI` يبقيها لفحص واجهة منفصل فقط.
- `Web.config` داخل الموديول يؤجل Request Validation إلى مستوى الحقول؛ حقلَا التفاصيل وحدهما يقبلان HTML ثم ينظفانه على الخادم. إعدادات بقية النظام لا تتغير.
- ابنِ Portal.vbproj بوضع Release مع OutDir إلى `tmp/information-build/`، ثم شغّل DeployLocal.ps1 لتحديث CRM.dll المحلي مع الاحتفاظ بنسخة سابقة والتحقق من hash.

## التحقق

- نجح بناء Portal والمكتبة؛ تحذير ADUsers في ActiveDirectorySearcher.vb موجود مسبقًا.
- نجحت ترجمة صفحات ASPX الست مع Site.Master بواسطة aspnet_compiler.
- Test.ps1 اجتاز 30 فحصًا لقواعد النشر والصلاحيات والإصدارات والسجلات والحذف وتعارض رقم الإصدار. يحذف فقط سجلات الاختبار التي أنشأها في finally.
- اختبار متزامن باتصالين منفصلين أثبت قبول حفظ واحد ورفض الحفظ الآخر القديم، دون إصدار أو سجل زائد.
- اختبارات HTML أثبتت الاحتفاظ بالتنسيق وإزالة المحتوى التنفيذي ورفض DTD والنص الفارغ، مع تحويل صحيح بين توقيت عمّان وUTC.
- فحص المتصفح الفعلي نفذ الإنشاء والتعديل باللغتين من CKEditor، العرض بحساب موظف، تسجيل الزيارات، الحذف والأرشيف وبقاء الإصدارات. أجريت الكتابة في قاعدة اختبار منفصلة بحسابات وهمية بعد عزل اتصال موقع الاختبار عن قاعدة النظام.
- فُحصت إتاحة صفحات العرض بخمس صفحات وهمية: منشورة فورًا، مجدولة متاحة، مسودة، مستقبلية، ومنتهية؛ ظهر الرابطان المتاحان فقط بالترتيب الصحيح. نجح زر نسخ الرابط. عند انتهاء الصفحة المفتوحة أثناء تحديث المؤقت يعاد المستخدم إلى مدخل الموديول وتُعاد مراجعة الإتاحة، بينما الرابط المباشر غير المتاح يعيد 404.
- ملفات LoginFixture وVerifyFixture محصورة بموقع الاختبار داخل tmp، ولا تُنشر في Portal.
- TestAccessRestore.ps1 اجتاز 35 فحصًا في قاعدة اختبار منفصلة: صلاحيات القائمة والرابط، اختيار أنواع متعددة، رفض النوع الفارغ/المجهول/غير الفعال، استقلال الصلاحيات عن الإصدارات، سجل قبل/بعد، حماية التعديل القديم، الاسترجاع ومرجعه، الاحتفاظ بالتاريخ والصلاحيات، تراجع الحفظ الجزئي، الجدولة المنتهية، ومنع الاسترجاع للصفحة المحذوفة. فحص المتصفح أكد حفظ الصلاحيات فقط دون زيادة رقم الإصدار، ثم استرجاع المحتوى مع بقاء المنع للموظف والسماح لمدير الفرع.

## جمهور العملاء

- `007_Audience_Schema.sql` يضيف Audience/AllCustomers وInformation_Page_Customers وهوية العميل في سجل الصفحات، ويجعل دالة العلامة المشتركة مقتصرة على جمهور الموظفين للهاتف والبوابة. `008_Audience_Procedures.sql` آخر تجاوز لإجراءات الحفظ/الوصول ويضيف Customer_InformationPages؛ لا تعد تشغيل 002/004 منفردين بعده. - `TestBrandAccess.ps1` يشغّل TestAudience.ps1 ضمن قاعدة معزولة ويختبر القائمة والرابط والهاتف والجمهور والتراجع والتوافق القديم. `CustomerPortal/Test-CustomerPortal.ps1` يشغل Test-PortalFlows.ps1 لاختبار نماذج الإدارة الحقيقية، التعقيم، العميل المحدد، اللغة والسجلات وسحب الصلاحية.

## AJAX administration

Manage.aspx and News/Manage_News.aspx share Controls/ContentManagement.ascx and content-management.js: compact statistics, brand/name/state filters, instant table search and responsive row cards. Add/edit use a same-page offcanvas and POST JSON payload/multipart image to Modules/ContentManagementAjax.aspx with session CSRF/current active administrator validation. Existing SQL procedures preserve content/access versions and audit. Successful writes reload persisted rows/statistics locally and reveal the saved row. The version badge opens History; row actions exclude versions/logs, and History has no logs link. The main menu links directly to Manage (administrator) or Index (employee); Index shows only authorized published cards. Legacy Edit.aspx remains a compatibility route, not a management action.

Deploy the matching Portal build, shared control, AJAX endpoint, Web.config scoped upload limit and assets together. No additional SQL migration is needed for this UI. Test-ManagementAjax.ps1 is invoked by CustomerPortal/Test-Dashboard.ps1 in an isolated database. DetailLanguageChecks.mjs verifies immediate bilingual title/body switching in the supported browser at desktop/mobile sizes.

History.aspx and Logs.aspx reuse the CRM management statistics/filter/table/mobile-card design. History local filters and the version-guarded restore modal use information-reports.js; no logs link is exposed there. Logs keep full server-side actor/action filters and 50-row batches; visit/change counters explicitly refer to the displayed batch. The management toolbar no longer has a manual refresh action. Preview links back to management. Customer.Master renders the currently authorized page names in a Template submenu without logging visits. DetailLanguageChecks.mjs also verifies full header/title/date direction and alignment in both languages.
